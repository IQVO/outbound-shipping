# Before the first release: outbound-shipping

The first merge to `main` runs `docker-publish` and `release` (`.github/workflows/ci.yml`). Two services built from the same template (pick-face-replenishment, task-interleaving) each needed a rework because packaging was missing or wrong when that moment came. This service has **passed that moment**: the first release, `v0.1.0`, was cut on 2026-11-11, registered and image-pinned in warehouse-infra, and **applied to the k3s cluster on 2026-11-12**: one `api` replica runs at `857edfd`. Every row, including the apply and the pre-created topics, is done. The page keeps its name and its rows as the service's packaging record; a row is deleted only when the service really does not have that part, and the PR says so.

`Dockerfile` and `.dockerignore` were generated from the fleet reference. The chart is not generated: it is shaped by what the service runs (six consumer groups, an MCP deployment, no frontend, projector, reports, sweep, A2A or separate relay) and was adapted from the sibling charts (`IQVO/dock-scheduling`, `IQVO/returns-processing`). Its components and values are listed in the [runbook](/docs/operations/runbook#helm-chart).

Every row was re-checked on 2026-11-11 against this repository, GitHub and warehouse-infra's `origin/develop` (the cluster read is a read-only `kubectl get`). Rows 14 to 19 were added on that date; rows 18 and 19 were re-checked read-only on 2026-11-13.
